## 0. 开始前（5 分钟）

### 0.1 备份现场数据

```bat
mkdir sounds\backup_test
copy sounds\config.json sounds\backup_test\
copy sounds\learned_*.wav sounds\backup_test\
:: 可选：录音也要保留
xcopy sounds\events sounds\events_backup /E /I /H
```

恢复：

```bat
copy /Y sounds\backup_test\config.json sounds\config.json
copy /Y sounds\backup_test\learned_*.wav sounds\
```

> ⚠ 学习成功会替换 `sounds/learned_*.wav` 并把新阈值写进 `sounds/config.json`；测试「学习成功」前一定先备份。
> ⚠ 「清空录音」会删除 `sounds/events` 下的文件（只删这里），测试前先备份或不点。

### 0.2 启动

1. 双击 `run_gui.bat`。
2. 终端出现本机 / 局域网地址；浏览器自动打开 `http://127.0.0.1:8765`。
3. 第一次 Windows 防火墙弹窗点「允许」。
4. 手机连**同一个 Wi-Fi**，打开终端里的局域网地址（如 `http://192.168.1.16:8765`）。

### 0.3 看页面第一眼

- [ ] 大字为「待机」，状态点为灰，模板数 >0（内置门铃存在）。
- [ ] 顶栏：`局域网 已开启 …`、`本机 …`、`上报 未配置`。
- [ ] 底栏：模板 / 命中 / 忽略三个读数。
- [ ] 按 F12 → Console 没有红色报错。

## 2. 逐条验收（M 级）

### AC-WEB-1 开箱即用

1. 双击 `run_gui.bat` → 浏览器自动打开。
2. 页面显示「待机」或「请先学习门铃」，模板可用。
3. 开始监听 → 播放一次门铃（或按真实门铃）→ 大字「门铃！」+ 得分 + 延迟 + 时刻。
4. **大字跟随实际声音**：至少 1.5 秒；有声时保持，声音结束约 0.4 秒后消失（最多约 12 秒）；真实监听不重亮旧类别（第二段是否会亮取决于识别是否产生新事件，8 秒冷却内不会）。经过静音后回到「监听中…」，副文案「上一声门铃 HH:MM:SS」。
5. 事件流只新增 1 条；第二段/长鸣不新增事件、不重复上报（D-22）。
6. 放大到 1920×1080、缩到 390×844，均不横向滚动、大字不折行错位。

### AC-WEB-2 学习流程 ⚠

1. 点「学习门铃」→ 大字「请按门铃」，副文案「第 1 次，共 3 次，还剩 N 秒」。
2. 按一次门铃 → 进入 2/3；再按 → 3/3。
3. 完成 → 「学习完成 ✓」+ 新阈值（0.50–0.62；只录到 1 次时固定 0.55）。
4. 点「开始监听」→ 再按门铃 → 命中。
5. 在 2/3 等待时刷新页面或换手机打开 → 仍显示当前进度。
6. 第二个页面点「学习门铃」→ 提示「另一台设备正在学习（n/N）」。
7. 学习中点「取消学习」→ 回到待机；再监听、再按门铃，仍用旧模板/旧阈值。

> 学习是声学采集：用真实门铃，或把手机放在电脑麦克风旁播放门铃录音。试听按钮在学习中是禁用的。
> 失败提示要区分：没听到 / 太小声 / 太短 / 不像门铃声；「这次和上几次差得比较多」只是提示，仍会采用。

### AC-WEB-5 误报复盘

### 长鸣 / 分段声音（D-22，重点）

用户反馈的三个现象在这里验收：

1. 点「试听 · 火警警报」（原始 8 秒）：第一段响时大字亮；两段之间的静音约 0.4 秒后回到待机/监听；第二段响时大字重新亮（试听演示按音频的有声区间重亮，不受 8 秒冷却影响）；事件流只有 1 条演示、不重复上报。
2. 点「试听 · 水壶鸣笛」（原始 12 秒）：大字在鸣笛期间保持；声音结束约 0.4 秒后消失。
3. 点「试听 · 门铃」：叮—咚有声时大字保持；文件末尾的静音段不应继续显示门铃。
4. 按一次真实门铃（“叮—咚”两段）：第一段有声时大字保持；两段之间静音超过约 0.4 秒后大字消失；第二段如果在 8 秒冷却内，不会再新增事件，也**不会**用上一次的类别硬亮（避免把别的声响显示成门铃）。
5. 真实火警两段、水壶长鸣：大字跟随实际声音；8 秒冷却之后还在响的部分不新增事件（全局冷却，不新增上报/CSV）。
6. 全程盯大字：不应在“已经没有声音”的区间继续显示类别——这就是实时性。

## 3. API 与边界（可选，但建议演示前跑一遍）

默认无口令时直接调用；开了口令就先用页面登录或加 Cookie。

```powershell
# 健康与状态
Invoke-RestMethod http://127.0.0.1:8765/api/health
$s = Invoke-RestMethod http://127.0.0.1:8765/api/state
$s.mode; $s.level_db; $s.config; $s.templates.count

# 监听开 / 关
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/listen -ContentType application/json -Body '{"on":true}'
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/listen -ContentType application/json -Body '{"on":false}'

# 学习冲突（先监听，再学习 → 409）
# 阈值越界（400）
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/settings -ContentType application/json -Body '{"threshold":1.2}'

# CSV
Invoke-WebRequest http://127.0.0.1:8765/api/export.csv -OutFile session.csv
Format-Hex session.csv | Select-Object -First 1     # 开头应为 EF BB BF

# 事件数据图（seq 换成实际事件号）
Invoke-RestMethod http://127.0.0.1:8765/api/events/1/analysis

# 单条录音（events[0].wav 换成实际地址）
Invoke-WebRequest "http://127.0.0.1:8765/api/recordings/xxx.wav" -OutFile rec.wav
```

手动检查：

- `/api/state` 的 `mode`、`on_air`、`stopped`、`config`、`iot.state` 与页面一致。
- 开学习时 `/api/learn` 返回 `{"ok":true,"takes":3}`。
- 监听中再开学习 → 409「请先停止监听再学习」。
- 正在学习时第二个 `/api/learn` → 409「另一台设备正在学习（n/N）」。
- 口令：未登录 `/api/state` → 401；`/api/auth` 正确 → 200 + Cookie；错误 → 401；清除口令 → 200。
- `?before=&limit=` 能加载更早事件；「载入更早」按钮可用。
- 「刷新模板」→ 模板数与列表更新，不重启。
- `/api/iot/test` 未配置 → `{"ok":false,"error":"未配置：请先填写…"}`。
- 关掉「局域网」后，手机访问返回 403「局域网访问已关闭，仅本机可访问」；本机页面仍可用；打开后手机恢复。
- 8525/8766 端口：先占用 8765，再启动 → 自动 8766，浏览器打开 8766。

单实例 / 端口：

```bat
:: 先启动一个，再双击 run_gui.bat：应只打开已有页面
:: 看端口占用
netstat -ano | findstr :8765
```

## 4. IoT / K10（有真实凭证时）

### 4.1 页面配置

1. 打开「上报」：填地址、端口、`Iot_id`、`Iot_pwd`、事件主题、状态主题；打开「启用上报」。
2. 「保存上报设置」→ 状态从「连接中」到「已连接」；板子在线需要收到心跳。
3. 「测试连接」→ 成功/失败都有中文结论（测试使用**已保存**的配置，先保存再测）。
4. 重开页面：`Iot_pwd` 只显示「已设置，留空表示不修改」；配置里没有明文。

### 4.2 本机模拟板子（不需要 K10）

`board/sim_board.py` 复用固件的 `BoardLink`（去重、心跳、重连、看门狗），只把界面换成终端：

```bat
:: 需要 sounds\iot.json 里已有可用凭证（页面保存后就会生成）
python board\sim_board.py status
python board\sim_board.py listen      :: 订阅状态主题 + 事件主题
:: 另开窗口/页面：点四类试听，终端应打印四类不同动作
python board\sim_board.py send --cls fire --short
```

### 4.3 K10 真板

1. 按 `board/config.example.py` 填 WiFi / Iot 凭证（`board/config.py` 不进版本库）。
2. 烧录/运行 `board/main.py`；屏幕出现「门铃」等。
3. 页面点四次试听（间隔 ≥4 秒）→ 板子四类表现不同：门铃短鸣蓝、敲两声、水壶长鸣黄、火警连续鸣红闪。
4. 打开「上报忽略事件」，放音乐 → 板子也收到忽略（看板子是否显示）。
5. 拔 WiFi 30 秒：页面「重连中」，板子在线标记冻结；恢复后自愈；发送/丢弃计数增加、不补发。
6. 检查 `sounds/iot.json` 与页面都不回显 `Iot_pwd`；日志不含凭证。

> 平台配额约 1 万条、建议间隔 ≥3 秒；演示 ≤50 条。K10 的 clientId 能否自定义见 R-1，真板第一件事验证。

## 5. 多端、断线与长稳

- [ ] 电脑 Chrome + Edge + 手机同时在线：三端状态一致，门铃命中误差 ≤1 秒。
- [ ] 手机 / 平板竖屏：无横向滚动；按钮可点；大字可读。
- [ ] 关闭页面 30 秒后重开：立即恢复状态与最近事件。
- [ ] 连续监听 10 分钟：页面不卡、事件流不丢、CPU 不持续升高。
- [ ] 2 小时长稳：内存增长 ≤50 MB；SSE 不断；日志无刷屏。
- [ ] 断网/恢复（拔 WiFi 或 `netsh`）：页面横幅 → 自动重连；识别与事件不崩。
- [ ] 3 个浏览器同时在线时：状态延迟仍 ≤1 秒。

## 7. 故障排查

| 现象 | 先查 |
|---|---|
| 手机打不开 | 同一 WiFi？页面「局域网」是否已开启？Windows 防火墙是否允许？地址是否用局域网而不是 127.0.0.1？ |
| 页面提示「连接已断开」 | 终端还在跑吗？8765 是否被别的程序占用？看 `netstat -ano \| findstr :8765` |
| 没有麦克风 / 打不开麦克风 | Windows 隐私设置允许麦克风；`run.bat devices` 看设备；页面「设置」换麦克风后重新开始监听 |
| 没有声音 | 页面「测试音」；「设置 → 播放设备」选扬声器；Windows 输出设备/音量；蓝牙耳机可能被选中 |
| 学习一直提示「不像门铃」 | 安静一点；用真实门铃或手机贴近麦克风播放门铃；不要放音乐/说话；可把学习次数改 2–3 |
| 学习「太小声」 | 手机/门铃靠近；系统麦克风增益不要过低 |
| 设置保存失败 / 录音保存失败 | 看终端「设置保存失败」；确认 `sounds` 可写；若是在 DSH 受限会话里由 AI 启动的服务，参考 ACL 修复记录；正常双击不受影响 |
| 口令忘了 | 编辑 `sounds/config.json` 删除 `password_hash`/`password_salt` 后重启（或从备份恢复） |
| 页面大字不更新 | F12 → Network → `/events` 是否有数据；Console 是否有异常；刷新一次 |
| 试听一次出两条 | 不应发生；检查是否在播放期间改了阈值/重启了监听；记录现象与日志 |
| 经典窗口打不开 | `run_gui_classic.bat`；确认 `src/pc_gui.py` 与 tkinter 可用 |
