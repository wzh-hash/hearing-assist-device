## 1. 背景与目标

当前识别只在本机生效：门铃响了，电脑上显示大字，仅此而已。本需求要求把**判定结果**经 DFRobot EasyIoT 平台（`iot.dfrobot.com.cn`）送到板子，由板子做灯光 / 声音 / 文字演示，让"物联网"这一段成为可看见、可复现的现场效果。

| 编号 | 目标 | 判定方式 |
|---|---|---|
| O1 | 真实门铃 → 板子动作 | 从按铃到板子开始亮/响 ≤2 秒 |
| O2 | 四类事件都能演示 | 门铃 / 敲门 / 水壶鸣笛 / 火警警报各触发一次，板子表现可区分 |
| O3 | 网络故障不毁识别 | 断网期间识别、页面、记录全部照常 |
| O4 | 现场无需人工干预 | 断网恢复后自动续上，不需要重启程序或重新配置 |
| O5 | 板子自己也能恢复 | 板子断电重启 ≤10 秒恢复接收，无需人工操作 |

```
[本机识别 + 网页] ──事件──▶ [平台·事件设备] ──订阅──▶ [行空板 K10]
[行空板 K10]      ──心跳──▶ [平台·状态设备] ──订阅──▶ [本机网页]
```

（音频始终留在本机；上行的只有"判定结果"这一条小消息）

| 在范围内 | 在范围外 |

| 凭证的保存方式 | 板子硬件选型（已定为 K10） |
| 板子在线检测 | 板子外壳、供电、安装方式 |
| **板子固件（K10，MicroPython，`board/`）** | 平台侧的数据分析、历史存储 |
| 板子侧表现（IOT-6） | 音频流上行（明确禁止） |

## 3. 术语

| 术语 | 含义 |
|---|---|
| 命中 | 判定为「是某类事件」，需要提示 |
| 忽略 | 听到了但不是目标事件，不上报 |
| 演示命中 | 由试听按钮触发、不来自麦克风的命中（带演示标记） |
| 事件设备 / 事件主题 | 平台工作间里为"本机 → 板子"创建的设备及其分配编码 |
| 状态设备 / 状态主题 | 平台工作间里为"板子 → 本机"创建的设备及其分配编码 |
| 心跳 | 板子周期性发的"我还在"消息（JSON，含 `hb` 键） |
| 客户端标识 | 连接平台时的身份，同一账号下每个连接必须唯一 |
| 保留消息 | 平台替新订阅者保存最后一条消息的机制；本需求**禁止**使用 |
| 全局冷却 | 识别层的 8 秒静默窗口，**任意类别**命中后都重新计时（非按类别） |
| 冻结标记 | 本机与平台的连接断开期间，"板子在线"标记保持最后已知状态、不刷新 |
| 端到端至多一次 | 一条事件从本机发出到板子动作，最多发生一次；协议重发可能造成重复，由板子按 `ts` 去重 |

## 5. 数据需求

### 5.1 结构化载荷

| 字段 | 类型 | 说明 |
|---|---|---|
| `v` | 整数 | 载荷版本，固定 `1` |
| `cls` | 字符串 | `doorbell` / `knock` / `kettle` / `fire` |
| `tier` | 字符串 | `L1` / `L2` / `L3` |
| `score` | 数值 | 模板相似度 0–1（**不是**置信度，D-19 备注） |
| `latency` | 数值 | 延迟，单位秒 |
| `ts` | 数值 | Unix 时间戳（秒，建议保留 3 位小数），**板子去重键** |
| `demo` | 布尔 | 是否演示命中 |

示例：

```json
{"v":1,"cls":"doorbell","tier":"L2","score":0.80,"latency":0.42,"ts":1763265600.123,"demo":false}
```

### 5.2 短码

| 事件 | 短码 |
|---|---|
| 门铃 | `DOOR` |
| 敲门 | `KNOCK` |
| 水壶鸣笛 | `KETTLE` |
| 火警警报 | `FIRE` |

### 5.3 心跳

```json
{"v":1,"hb":1,"dev":"k10-01","ts":1763265600.000}
```

| 要求 | 说明 |
|---|---|
| 长度 | ≤64 字节 |
| 可识别 | 接收端以 `hb` 键判定为心跳，不得用 `DOOR` 等短码当心跳 |
| 内容 | `dev` 与 `ts` 非必需；`v` 与 `hb` 必需 |

### 5.4 身份约束

| 编号 | 约束 |
|---|---|
| D-1 | 同一账号下，本机与板子必须使用不同的客户端标识；相同会导致双方互相踢下线 |
| D-2 | 页面必须在配置处给出 D-1 的提示文字 |
| D-3 | 配置项默认可直接使用：接入地址与端口预填平台地址，其余由用户填写 |
| D-4 | 事件主题与状态主题必须来自**两个不同的平台设备**，不得复用同一编码 |
| D-5 | 平台"重新生成"`Iot_id`/`Iot_pwd` 后必须同步更新配置，否则表现为「账号或密码错误」 |

## 8. 验收

> 全部验收项只依赖 M 级要求（D-05）。

### AC-IOT-1 正常链路（M）

1. 填写 `Iot_id`、`Iot_pwd`、事件主题、状态主题，打开上报开关。
2. 状态在 10 秒内变为「已连接」。
3. 点页面「试听 · 门铃」。
4. 板子 ≤2 秒内显示「门铃」并短鸣。

**通过标准**：页面"最后发送"时间更新；板子动作与类别一致；发送计数 +1、丢弃计数不变。

### AC-IOT-2 断网与恢复（M）

1. 监听中禁用本机网络。
2. 播放门铃 → 页面照常出大字，识别不受影响。
3. 状态变为「重连中」，丢弃计数增加；板子在线标记**冻结**不翻红。
4. 恢复网络 → ≤5 秒回到「已连接」。
5. 恢复后板子不得收到断网期间的旧事件。

**通过标准**：识别零中断、无补发、状态自愈。

### AC-IOT-3 凭证错误（M）

1. 故意填错 `Iot_pwd` → 状态显示「失败」+ 可读中文原因。
2. 识别、页面、试听全部照常。
3. 改回正确密码 → ≤2 秒恢复，无需重启。

**通过标准**：不出现反复报错刷屏，不影响本地功能。

### AC-IOT-4 板子重启（M）

1. 板子断电 10 秒后上电。
2. ≤10 秒自动重连。
3. 页面「板子在线」由离线变为在线。
4. 再试听一次 → 板子正常动作。

**通过标准**：全流程无需人工干预。

### AC-IOT-5 四类事件全覆盖（M）

依次试听门铃、敲门、水壶、火警 → 板子四次表现各不相同且与 IOT-6.1–6.4 一致。

### AC-IOT-6 重复报警检查（M）

1. 用试听连续播放同一类事件 **4 次，间隔 4 秒** → 板子应触发 **4 次**提示，不得出现"一次播放触发两次"。
2. 用真实门铃在 **3 秒内连按 2 次** → 只应产生 **1 次**命中与 1 次上报（全局 8 秒冷却，D-07）。

**通过标准**：演示路径不丢不重；真实路径不被冷却之外的规则干扰。

### AC-IOT-7 重复投递去重（M）

用本机第二个订阅者手工向事件主题发布：

1. 同一 `ts` 发两次 → 板子只动作一次。
2. 不同 `ts`、同一类别发两次 → 板子动作两次。

**通过标准**：去重只看 `ts`，不误吞"同类连续事件"。

### AC-IOT-8 长稳与配额（M）

连续运行 2 小时（监听 + 每 8 秒一次试听）：无连接泄漏、内存增长 ≤50 MB、发送总数与页面计数一致、无未捕获异常。

### AC-IOT-9 心跳与离线（M）

1. 拔掉板子电源 → 120 秒后页面显示「板子离线」，事件流不出现心跳记录。
2. 本机断网 60 秒 → 在线标记保持最后状态（冻结），恢复后 120 秒内无心跳才判离线。

## 9. 不在本需求范围

- 从板子或页面反向控制识别；
- 云端历史存储、跨天统计、多板子广播；
- 断线期间事件的补发与补偿；
- 公网访问与安全加固（仅内网演示）；
- 板子外壳、供电、安装等机械工作；
- 音频流上行。
