# 需求 02 · 网页前端（取代桌面窗口）

**版本** v1.1 ｜ **状态** 已评审（2026-11-15）｜ **关联** 需求 01（物联网上报）、`docs/decisions.md`

> 只描述要求与验收，不含实现方案。v1.0 → v1.1 的改动见文末「变更记录」。

## 0. 评审结论摘要

- 前端是**新建**：仓库里没有 HTTP 服务、没有端口、没有单实例锁，本需求不是改造桌面窗口。
- 识别与网页**同进程**（web 线程 + 识别线程共享状态），服务端只有一份状态机，浏览器只是视图（D-15、D-17）。
- 局域网访问**默认开启**（只监听内网网卡），页面常驻显示地址；口令可选、默认空（D-14）。
- 试听从**电脑音箱**出声，播放期间抑制识别（D-06）；试听命中绕开 8 秒冷却（D-07）。
- `run_gui.bat` 改为启动网页，经典窗口由 `run_gui_classic.bat` 回退（D-16）。
- 验收只走 M 项；WEB-7.4 明细升 M，WEB-7.5 录音回放降为加分（D-05）。

## 1. 背景与目标

现在的界面是一个桌面窗口：只能坐在电脑前看，使用者与照护者看不到，手机看不到，投影也没法用。本需求要求把界面改成**浏览器里的页面**，并让这个页面成为唯一前端——原来的桌面窗口退役（保留代码可回退，但不再作为产品界面）。

| 编号 | 目标 | 判定方式 |
|---|---|---|
| W1 | 功能不减 | 旧界面的每一项能力在新页面都有对应入口（对照表 100% 覆盖，见 §4 WEB-10 与 D-11） |
| W2 | 多端可见 | 同一网络内手机/平板/投影打开的页面显示同一状态，误差 ≤1 秒 |
| W3 | 状态不丢 | 任何时刻刷新、换设备打开，都能看到当前真实状态与最近事件 |
| W4 | 双击即用 | 沿用原有启动方式，不需要命令行、不需要安装额外工具 |
| W5 | 断线不慌 | 服务短暂不可达时页面明示并在恢复后自动回到正常 |

## 2. 系统边界

```
[麦克风] ──▶ [本机识别与状态] ──▶ [浏览器页面（本机 / 手机 / 投影）]
                    │
                    └──▶ [IoT 上报，见需求 01]
```

识别算法与物联网上报不属于本需求（见需求 01）；本需求只管"怎么把状态给人看、怎么让人操作"。

| 在范围内 | 在范围外 |
|---|---|
| 页面信息架构、交互、可读性 | 识别算法与声学参数（C-1） |
| 学习 / 监听 / 试听 / 设置的操作入口 | 物联网协议细节（仅要求"显示上报状态"，见 WEB-11） |
| 事件记录、统计、导出、录音回放 | 公网访问、账号体系 |
| 启动方式与旧界面退役 | 波形/频谱类可视化（含 pc_dash 曲线，D-11） |
| 状态总线与多端同步 | 移动端原生 App、多语言 |

## 3. 术语

| 术语 | 含义 |
|---|---|
| 大字区 | 页面最显眼的状态区，显示「请先学习门铃 / 监听中… / 门铃！」 |
| 事件流 | 每次判定一行的滚动列表 |
| 试听命中 | 由试听按钮触发、不来自麦克风的命中（带标记） |
| 模板 | 参与匹配的参考音；无模板时不能监听 |
| 高级设置 | 阈值、门控、麦克风、播放设备等参数区，默认折叠 |
| 状态总线 | 服务端唯一的状态对象；所有页面读它，所有操作改它 |
| 抑制窗口 | 试听播放期间临时暂停识别的时段 = 播放时长 + 0.5 秒尾音 |
| 端到端至多一次 | 上报链路的投递保证，见需求 01 IOT-3.10 |

## 5. 数据需求

### 5.1 页面必须能展示的事件字段

| 字段 | 说明 |
|---|---|
| 时刻 | HH:MM:SS |
| 结论 | 命中 / 忽略 |
| 类别 | 门铃 / 敲门 / 水壶鸣笛 / 火警警报 |
| 等级 | L1 / L2 / L3 |
| 得分 | 0–1，两位小数 |
| 置信度 | 0–1，两位小数（与 `score` 不同，见需求 01 IOT-3.15） |
| 延迟 | 毫秒整数 |
| 时长 | 秒，两位小数 |
| 试听标记 | 是 / 否 |
| 声学指标 | 调性、调制、衰减、稳定度、主频比、敲击数、脉冲数 |
| 录音引用 | 该次判定音频（可回放） |

### 5.2 页面可配置项

| 配置 | 默认 | 范围 |
|---|---|---|
| 判定阈值 | 0.60（未学习；学习后由 config 覆盖，落在 0.50–0.62） | 0.40–0.95 |
| 门控 | 8 dB | 6–30 |
| 麦克风 | 系统默认 | 设备序号 |
| 播放设备 | 扬声器类 | 设备序号 |
| 学习次数 | 3 | 1–5 |
| 局域网访问 | **开启** | 开 / 关 |
| 访问口令 | 空 | 字符串 |
| 端口 | 8765 | 8765–8767 自动退让 |
| 上报相关 | 关闭（默认） | 见需求 01 |

### 5.3 CSV 导出列（顺序固定）

`时间, 类型, 类别, tier, 是否试听, 得分, 置信度, 延迟ms, 时长s, 调性, 调制, 衰减, 稳定度, 主频比`

- 时间：`YYYY-MM-DD HH:MM:SS`
- 类型：`命中` / `忽略`
- 文件：`session_YYYYMMDD_HHMMSS.csv`，UTF-8 带 BOM
- 心跳、连接事件不写入

### 5.4 录音文件

每次判定保存到 `sounds/events`，命名含时间戳、结论、类别、得分、置信度；同目录最多 300 个，超出删除最旧；页面可单条播放/下载、可一键清空；**不提供**打包导出（D-18）。

## 8. 验收

> 全部验收项只依赖 M 级要求（D-05）。

### AC-WEB-1 开箱即用（M）

1. 双击 `run_gui.bat` → 浏览器自动打开。
2. 页面显示「请先学习门铃」或「开始监听」已可用（内置模板存在时）。
3. 点「开始监听」→ ≤1 秒进入监听态，音量条随说话跳动。
4. 播放一次门铃 → ≤1 秒出现「门铃！」+ 得分 + 延迟 + 时刻。
5. 3.5 秒后回到「监听中…」，副文案显示「上一声门铃 HH:MM:SS」。

**通过标准**：5 步无卡顿、无报错、无需刷新。

### AC-WEB-2 学习流程（M）

1. 点「学习门铃」→ 显示「请按门铃（1/3）」。
2. 按一次 → 进入 2/3；再按 → 3/3。
3. 完成 → 显示「学习完成 ✓」与新阈值。
4. 点「开始监听」→ 再按门铃 → 命中。
5. 在第 2 次等待时刷新页面 → 仍显示「请按门铃（2/3）」。

**通过标准**：进度不丢；除"再按一次"外不出现其他错误。

### AC-WEB-3 手机查看（M）

1. 启动后页面顶部显示「局域网已开启」与地址（默认，无需手动开启）。
2. 手机（同一 WiFi）打开 → 2 秒内完整显示。
3. 手机点「开始监听」→ 电脑页面同步进入监听态。
4. 门铃命中 → 两端同时出大字，误差 ≤1 秒。

**通过标准**：手机竖屏无横向滚动、按钮可点、大字可读。

### AC-WEB-4 断线与恢复（M）

1. 关闭服务 → 页面 ≤5 秒显示「连接已断开，正在重试…」。
2. 重新启动服务 → 页面无需刷新自动恢复，状态与事件补齐。

### AC-WEB-5 误报复盘（M 明细 / S 回放）

1. 放一段音乐 → 出现"忽略"记录。
2. 点开 → 看到调性、调制、衰减、稳定度、主频比。
3. （加分）可回放该次录音。
4. 导出 CSV → Excel 打开无乱码，列齐全。

### AC-WEB-6 故障与边界（M）

| 场景 | 期望 |
|---|---|
| 端口被占用 | 自动退让到 8766/8767；全占则中文提示，不异常退出 |
| 无麦克风 | 提示"未找到麦克风"，页面可用，监听按钮给出原因 |
| 3 个浏览器同时在线 | 状态一致，互不干扰 |
| 页面关闭后重开 | 立即显示当前状态与最近事件 |
| 上报未配置 | 页面显示"未配置"，识别与页面照常 |

### AC-WEB-7 多端并发与冲突（M）

1. 手机与电脑同时点「开始监听」→ 两端都进入监听态，不报错。
2. 一个端点「学习门铃」，另一个端点「学习门铃」→ 后者显示「另一台设备正在学习（n/N）」。
3. 学习中刷新页面 → 进度仍在。

### AC-WEB-8 重复双击（M）

连续双击 `run_gui.bat` 两次 → 只有一个识别实例；第二次直接打开已有页面并退出，不出现第二个麦克风占用。

### AC-WEB-9 试听不重复命中（M）

1. 监听中点一次「试听 · 门铃」→ 大字出一次、事件流新增 1 条（带试听标记）、上报计数 +1。
2. 连续试听 4 次（间隔 4 秒）→ 事件流 4 条、板子 4 次动作，无"一次播放两条"。
3. 播放期间对着麦克风说话 → 不产生额外事件（抑制窗口内）。

### AC-WEB-10 旧界面回退（M）

双击 `run_gui_classic.bat` → 经典窗口打开，学习 / 监听 / 试听 / 高级设置行为与改动前一致。
