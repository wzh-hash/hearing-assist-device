# 门铃识别 · 单场景 Demo（纯识别版）

给听障人士的 Demo：电脑麦克风听到声音，判断“是不是门铃”，命中后大字提示。

**设计原则：主界面只留两件事——「学习门铃」「开始监听」。阈值、门控、麦克风全部收进「高级设置」，默认不用碰。**

```
麦克风 → 能量门控（50ms 块） → 边听边判（0.35s 起） → NCC 模板匹配（多模板 + 时间伸缩变体）
      → 超过阈值 + 调性检查 → 大字「门铃！」+ 得分 + 延迟
```

实测：从门铃响起到界面提示约 **0.4 秒**（处理块 50ms + 提前判定 0.35s + 界面刷新 25ms）。

---

## 一、怎么用（就两步）

**双击 `run_gui.bat`**：

1. 点 **「① 学习门铃（按 2 次）」**
   - 界面提示“请按门铃（1/2）”
   - 按一次门铃（或手机播放一次门铃声音），重复 2 次
   - 只有“没听到 / 太小声 / 有效声音太短”才会要求重按；最多尝试 8 次
   - 只录到 1 次也算学习成功（会提示“建议再学一次”）
2. 点 **「② 开始监听」**
   - 再按门铃 → 大字 **「门铃！」** + 得分 + 延迟

## 三、学习流程做了什么（为什么用户不用调参）

| 环节 | 自动处理 |
|---|---|
| 采集 | 听到声音后**固定录 2.4 秒**（带 0.3 秒预录），保住“叮—咚”中间停顿，再裁掉尾部余音 |
| 门控 | 学习时要求比底噪高 **12dB** 才算一次声响；监听时默认 **8dB**（噪声环境更容易触发） |
| 只拒两种 | 太小声（峰值 < -40dBFS）、有效声音太短（< 0.35 秒） |
| 只提示不拒 | 声音偏响（削波）、和上几次差异较大 —— 都会提示，但仍然采用 |
| 次数 | 录满 2 次即完成；最多尝试 8 次；只录到 1 次也算成功（附提示） |
| 阈值 | 按两次录音的一致性算：`一致性 − 0.12`，限幅在 **0.50~0.62**；开始监听时若阈值高于模板一致性推算值，会**自动下调** |
| 模板 | 保存为 `sounds/learned_*.wav`，匹配时自动生成 ±5% 时间伸缩变体 |

> 之前的版本用“相似度硬性拒绝”来保证质量，但环境噪声会让同一种门铃也被判低分，
> 导致“明明没改条件却一直提示错误”。现在改成：只做物理质量检查，一致性只作提示。

**阈值为什么要按一致性算**：同一门铃的两段录音本来就只能到 0.6 左右（手机位置、环境差异）。
如果阈值设在 0.62，现场怎么放都差一点点——表现就是“识别不到”。
现在阈值 = 模板一致性 − 0.12（限幅 0.50~0.62），并且开始监听时会再自检一次：
若保存的阈值高于当前模板推算值，自动下调并在日志里提示，不需要重新学习。

## 四、怎么验证它工作正常

### 快速（2 分钟）

1. 学习门铃（按 2 次）
2. 开始监听，放 5 次门铃 → 应命中，延迟 < 1 秒
3. 说一段话、放一段音乐 → 不应命中

### 严格（演示前）

| 测试 | 做法 | 合格线 |
|---|---|---|
| 麦克风 | 监听时说话，看音量条跳动 | 明显跳动，底噪 -60~-45dB |
| 学习质量 | 一次就出现「学习完成 ✓」 | 不应反复要求重按 |
| 正样本 | 连续放 10 次门铃 | ≥ 8 次命中 |
| 延迟 | 看大字下延迟数字 | < 1 秒 |
| 负样本 | 说话 10s、音乐 10s、敲桌、关门、拍手 | 0 次命中 |
| 稳定性 | 连放 3 次（间隔 3 秒） | 3 次都命中 |

不达标时只动两个滑块（高级设置里）：
- **漏报** → 阈值降 0.03，或门控降到 6~8（噪声环境默认就是 8）
- **误报** → 阈值升 0.03，或门控升到 10~12

### 离线自检（不用麦克风、不出声）

```bat
run.bat selftest
```

## 五、确定性测试结果（不经过麦克风，直接喂音频）

用同一段门铃生成 2 次带差异的“现场录音”学习，再喂入检测器（50ms 块，阈值 0.50）：

| 场景 | 结果 |
|---|---|
| 正常音量连续 3 次 | **3/3 命中**，score 0.77，声音开始后 **0.4 秒**命中 |
| 小声 + 噪声 | **3/3 命中**，score 0.64，同样 0.4 秒 |
| 白噪声 / 环境响动 | **0 次误报** |
| 学习一致性 | 0.50~0.68 |
**噪声环境专项（学习后的模板，门控 8dB，阈值 0.60）**

| 场景 | 结果 |
|---|---|
| 粉红噪声，信噪比 20 / 10 / 5 dB | 命中 2/3、1/3、2/3，命中时得分 0.81~0.86 |
| 风扇低频噪声，信噪比 20 / 10 / 5 dB | 命中 3/3、2/3、1/3，得分 0.79~0.85 |
| 纯粉红噪声（没有门铃） | **0 次误报**（最好 0.47） |
| 纯低频噪声 | **0 次误报**（最好 0.36） |

> 噪声环境下“有时漏”，主要不是匹配分数问题（5dB 信噪比得分仍有 0.8 左右），
> 而是触发时机：噪声先触发采集、真正的门铃被挤在采集中间。
> 已加入“采集中遇到明显更响的新起音就重新开始采集”，并把默认门控从 12dB 降到 8dB。

> 注意：这是“同一段音频 + 模拟差异”的结果，真实房间里还要按第四节实测一次。

## 八、已知限制（演示时照实说）

- 只认**学过的那个门铃声音**，不认“所有门铃”；
- 学习时和演示时的**手机位置、音量尽量一致**；
- 电脑喇叭播放时，Windows 回声消除可能把声音从麦克风里抹掉（偶发没反应）——**用手机播放不受影响**；
- 环境很吵时：先降「判定阈值」0.03，再把「门控 dB」降到 6~8；反了会更容易漏；
- Demo 级识别，不是产品级声学模型。

## 十、误报防护：两级判定（重要）

门铃和“大声说话”都有谐波，光看调性不够，所以判定分两条路：

### 路径 A：快速命中（约 0.55 秒）

条件：**匹配分数 ≥ 阈值 + 0.20** 且 **调性 ≥ 3000** 且至少听了 0.4 秒。
真实门铃满足（干净门铃 score 0.98 / 调性 11000+），说话不满足（score 最高 0.51 / 调性 <1000）。

### 路径 B：复核（约 0.9 秒）

条件：分数过阈值、但没达到快路径（例如小声或噪声里的门铃）。
此时继续听到 **0.85 秒**，检查**包络调制**：

| 声音 | 2~8Hz 调制占比（音节起伏） |
|---|---|
| 门铃（1 秒窗口） | 15% ~ 30% |
| 门铃 + 噪声 | ~28% |
| 说话（正常 / 更大声） | **85% ~ 89%** |

调制 ≤ 55% 才判定为门铃。说话的音节一起一伏，会被这条挡掉。

### 界面显示 3.5 秒自动复位

命中后大字「门铃！」显示 **3.5 秒**，然后自动回到「监听中…」，
标题下方保留「上一声门铃 20:22:27」。这样门铃不响了界面不会一直挂着“门铃”。

### 三个地方生效的调性检查

1. **学习时**：调性 < 300 的录音不算门铃（提示“这次不像门铃声”），不存成模板；
2. **命中时**：上面的两级判定；
3. **加载模板时**：自动跳过调性过低的参考音。

> 曾经出现“大声说话被识别成门铃”，原因是语音元音也有谐波、调性不低。
> 加入“包络调制复核”后，说话（含更大声）误报为 0。

**验证结果（50ms 块，阈值 0.50）**：

| 场景 | 结果 |
|---|---|
| 门铃正常 | 3/3 命中，约 0.55 秒，score 0.86 |
| 门铃小声 | 3/3 命中，约 0.55 秒，score 0.74 |
| 说话样（正常） | **0 次误报** |
| 说话样（更大声） | **0 次误报** |
| 白噪声 | **0 次误报** |

## 十二、更多声学参数（v2 判定）

除匹配分数、调性、包络调制外，又加入三个参数，命中要求全部通过：

| 参数 | 含义 | 门铃 | 说话 / 音乐 | 阈值 |
|---|---|---|---|---|
| 包络调制 | 2~8Hz 音节起伏占比 | 15%~30% | 85%~99% | ≤ 50% |
| 衰减速度 | 起音后包络下降 dB/s | -25 ~ -35 | 约 0 | ≤ -8 |
| 音高稳定度 | 最长稳定音高段占比 | 0.2~0.44 | <0.1（音乐 1.0 但主频不符） | ≥ 0.10 |
| 主频比例 | 事件主频 / 模板主频 | 约 1.0 | 说话 0.1~0.2、音乐 0.2~0.3 | 0.5 ~ 2.0 |

实测（模板主频 2469Hz）：

| 场景 | 结果 |
|---|---|
| 门铃正常 | 命中，0.55 秒，score 0.86，主频比 1.00 |
| 门铃小声 | 命中，0.55 秒，score 0.74，主频比 1.00 |
| 说话样 | **0 次误报**（主频比不合格） |
| 音乐样 | **0 次误报**（主频比不合格） |
| 白噪声 | **0 次误报** |

同时把报警冷却从 3 秒加到 **8 秒**，避免同一段持续声音反复报警。

                 │      │      │       │      │      └ 音高稳定度
                 │      │      │       │      └ 衰减 dB/s

                 │      │      └ 调性

保留最近 300 个。高级设置里点 **「📂 事件录音」** 可直接打开文件夹。

## 十四、四类事件（开箱即用，含敲门 / 水壶 / 火警）

除了可学习的门铃，程序内置了另外三类事件，**不需要学习**：

| 事件 | 分级 | 识别方式 | 实测触发点 |
|---|---|---|---|
| 门铃 | L1 | NCC 模板匹配（内置干净门铃 + 可选学习） | 约 0.5 秒 |
| 敲门 | L1 | 声学结构：低频敲击脉冲 2 次以上、无持续音调 | 约 1.7 秒（3 下后） |
| 水壶鸣笛 | L2 | 高频窄带持续音 ≥0.6 秒 | 约 1.0 秒 |
| 火警警报 | L3 | T3 脉冲串（≥3 个脉冲 + 规则间隔） | 约 2.2 秒 |

**依据（不是模板，是物理特征）**：
- 敲门：低频能量快速起音的脉冲串，几乎没有高频窄带成分
- 水壶：2~5kHz 窄带能量持续，音高稳定
- 火警：2~5kHz 脉冲串，间隔约 0.5 秒（标准 T3），与环境噪声明显不同

### 界面

- 主按钮仍是 **① 学习门铃 / ② 开始监听**
- 新增 **试听按钮**（门铃 / 敲门 / 水壶 / 火警）：点一下直接播放内置音频，用于演示和自测
- 高级设置里新增 **播放设备**：默认自动选「扬声器」，不要选耳机（否则麦克风录不到）
- 命中后按分级显示：L1 蓝 / L2 橙 / L3 红，3.5 秒自动复位
- 数据面板事件列表新增「事件」列（门铃 / 敲门 / 水壶鸣笛 / 火警警报）

### 测试方法

`at
run.bat selftest
`

不经过麦克风，直接喂内置音频，检查：4 类全部命中且类别正确、语音/白噪声/音乐/纯音 0 误报。

### 现场演示建议

1. 电脑音量保持中等，**播放声音靠近笔记本麦克风**（30~50cm）
2. 用界面上的「试听」按钮播放最稳（同一台电脑、可控音量）
3. 手机播放也可以，但音量和距离会影响识别
4. 火警需要听到 3 个脉冲（约 2.2 秒）才会报警，这是为了和“水壶持续音”区分

### 关于真实环境的说明

干净的音频判定 4/4 全部正确；但经过扬声器+麦克风的真实声学链路后，
受房间混响、麦克风自动增益、环境噪声影响，识别率会下降。
如果现场测试不理想，可以：
- 关闭麦克风「自动增益 / 音频增强」后重新测试
- 提高播放音量（但不要削波，界面音量条不要在顶部）
- 把声音源靠近麦克风

## 十五、门铃也不再需要学习 + 环境自检

### 门铃开箱即用

模板里默认包含内置门铃（sounds/builtin_audio/doorbell.wav），打开程序就能监听，
主按钮改为 **「① 学习门铃（可选）」**——学习只是用来提高准确率，不学也能用。

### 环境自检（新增）

音量条右侧会实时显示环境状态：

| 显示 | 含义 | 怎么办 |
|---|---|---|
| 环境安静 | 正常 | 可以监听 |
| 环境偏吵（橙色） | 底噪较高，容易漏检/误判 | 靠近声源、关掉电视/音乐 |
| ⚠ 麦克风削波（红色） | 麦克风增益过高，声音被削平 | 关掉「麦克风增强/AGC」，或把系统输入音量调低 |

### 判定规则已收紧

为减少噪声误报，四类判定门槛都提高了：

- 敲门：≥3 次低频敲击、无持续音、脉冲极短（≤0.10s）
- 水壶：高频窄带持续 ≥0.70s 且窄带集中度 ≥0.75
- 火警：T3 脉冲串（≥3 脉冲 + ≥2 个规则间隔 + 集中度 ≥0.55）
- 门铃：模板匹配 + 调性/衰减/音高稳定复核

### 触发更灵敏

底噪估计改为「长时底噪 + 短时底噪」双门控：对**突然出现的新声音**更敏感，
在有一定环境噪声的房间里也能触发，同时用更严的判定规则防误报。

### 仍然识别不准时

真实声学链路（扬声器/手机 → 麦克风）受房间混响、麦克风自动增益影响很大。
本机实测发现：录音电平能到 0 dBFS（削波），且 60~1000Hz 环境能量很高，
说明要么环境很吵，要么麦克风增强开得太大。这属于采集问题，换任何识别算法都会受影响。

建议按顺序排查：
1. 看界面「环境状态」：显示红色/橙色就先解决麦克风增益或环境噪声
2. 用「试听」按钮播放，声音离笔记本 30cm 左右
3. 若用手机播放：手机音量 60% 左右，靠近笔记本麦克风
4. 仍不行的话，把界面日志的最后几行发我（含 敲击/脉冲/持续/得分）

## 十六、修复：敲门太小声（实测数据）

### 问题定位

用「扬声器播放 → 麦克风录音」逐类实测，得到麦克风实际收到的信噪比：

| 事件 | 修复前 SNR | 原因 |
|---|---|---|
| 门铃 | +19.5 dB | 正常 |
| **敲门** | **+1.8 dB** | 几乎等于环境噪声，必然漏检 |
| 水壶 | +8.0 dB | 偏弱 |
| 火警 | +31.7 dB | 正常 |

原因：四段内置音频的响度不统一——敲门文件峰值只有 -13dBFS（门铃 -1.8、火警 0），
而且敲门的能量集中在 60~500Hz，笔记本小喇叭根本放不出来。

### 修复

把四段内置音频统一做 **RMS 响度归一化**（目标 -18dBFS，峰值留余量）。

修复后实测：

| 事件 | 修复后 SNR | 提升 |
|---|---|---|
| 敲门 | **+20.4 dB** | **+18.6 dB** |
| 门铃 | +18.3 dB | -1.2 |
| 水壶 | **+13.4 dB** | **+5.4 dB** |
| 火警 | +20.2 dB | -11.5（原来过响，反而更均衡） |

### 新增声学参数

判定用的特征从 5 个扩到 10 个（都写进日志，便于现场排查）：

- 原有：匹配分数、调性、包络调制、衰减速度、音高稳定度、主频比例
- 新增：窄带集中度、低频敲击次数、最短爆破时长、低频调性、脉冲持续时长

### 结论

- **敲门漏检的主因确实是音量**，归一化后信噪比提高 18.6dB
- 但真实环境的房间噪声仍然影响识别：安静音频自检 4/4 全过，
  经扬声器+麦克风后只有火警稳定识别，其余受环境噪声影响
- 建议：在安静环境用「试听」按钮测试，或看界面「环境自检」确认底噪水平
