# 听障人士感知器

**面向听障人士的家庭声音感知器（接近成品）**：电脑麦克风识别门铃 / 敲门 / 水壶鸣笛 / 火警警报，通过网页大字、等级灯光与（可选）震动/蜂鸣提醒，并经 EasyIoT 同步到行空板 K10。

> **产品状态**：接近成品（v1.x），不是演示样机。使用者是听障人士及其照护者，部署环境为家庭/居所；下文所有"现场"均指实际安装与使用。

**产品界面是网页**：双击 `run_gui.bat` → 自动打开浏览器里的「听障人士感知器」。局域网内手机/平板/投影可同时打开；经典桌面窗口保留为 `run_gui_classic.bat`。

**设计原则：主界面只留两件事——「学习门铃」「开始监听」。阈值、门控、麦克风全部收进「设置」，默认不用碰。**

> **需求与设计（唯一真相源）**：`docs/REQ-01-iot.md`、`docs/REQ-02-webui.md`、`docs/plan.md`、`docs/decisions.md`、`docs/DESIGN-webui.md`。
>
> 识别算法、声学参数、判定逻辑未改动；网页服务端只在外围接线（`pc_web.py` + `web/`），与识别、播放、IoT 同进程。

```
麦克风 → 能量门控（50ms 块） → 边听边判（0.35s 起） → NCC 模板匹配（多模板 + 时间伸缩变体）
      → 超过阈值 + 调性检查 → 大字「门铃！」+ 得分 + 延迟
```

实测：从门铃响起到界面提示约 **0.4 秒**（处理块 50ms + 提前判定 0.35s + 界面刷新 25ms）。

## 一、怎么用（就两步）

**双击 `run_gui.bat`**，浏览器会自动打开控制台（本机 `http://127.0.0.1:8765`）。

1. 页面显示「待机」且模板数大于 0 时，点 **「开始监听」**；没有模板先点 **「学习门铃」**。
   - 学习：按页面提示按门铃（当前设置为 1 次；次数可在「设置」改 1–5）；只录到 1 次也算成功，会提示再学一次。
   - 学习中可以取消；取消后模板和阈值保持不变。
2. 再按门铃 → 大字 **「门铃！」** + 得分 + 延迟；大字**跟随声音**：至少 1.5 秒，声音持续时顺延，声音结束约 0.4 秒后消失；分段/长鸣在静音段不硬撑（D-22）；真实监听不重亮旧类别，试听会在同一段音频的第二段重新点亮，事件仍只记一条。
3. 试听：点「门铃 / 敲门 / 水壶鸣笛 / 火警警报」会从**电脑音箱**出声，并生成一条带「试听」标记的命中；播放期间不会产生额外的真实命中。
4. 手机：与电脑连同一 Wi-Fi，打开页面顶部「局域网」地址；第一次 Windows 防火墙弹窗点「允许」。
5. 回退：`run_gui_classic.bat` 打开经典桌面窗口，行为与改动前一致。

启动后终端会打印本机与局域网地址；`Ctrl+C` 停止服务。关闭页面不会停止识别，重新打开会立即恢复状态与最近事件。

## 产品运行：自启、隐私与自动恢复

### 开机自启（推荐）

```bat
tools\install_autostart.bat
```

安装后优先注册任务计划程序（登录触发、`pythonw.exe` 隐藏运行、失败重试）；当前账户没有注册权限时，自动退回「启动」文件夹快捷方式 + `tools/watchdog.py` 看门狗。两种方式都是隐藏启动，看门狗会把崩溃的服务拉起来。
卸载：`tools\uninstall_autostart.bat`。日志：`sounds\logs\product.log`、`sounds\logs\watchdog.log`。

### 隐私与录音

- 第一次打开页面会弹一次说明：录音存本机、最多 300 条、不上传、局域网可访问；确认后不再弹。
- 「设置 → 录音与隐私」可以关闭判定录音（默认开）；已有录音在「记录」里一键清空。
- 录音与识别结果只留在本机；只有你在「上报」里主动配置的服务会收到事件结果。

### 自动恢复（看门狗）

- **麦克风断开**：页面提示「麦克风断线，正在自动重试」，服务按 2 秒起、最长 30 秒的退避自动重连；恢复后提示消失。
- **进程崩溃**：看门狗每 10 秒探活，连续 2 次失败自动拉起（约 20 秒）；任务计划程序另有失败重启兜底。页面在服务恢复后自动重连并补齐状态。
- **板子离线**：页面「上报」与板子心跳显示离线；识别与网页大字不受影响。

## 三、学习流程做了什么（为什么用户不用调参）

| 环节 | 自动处理 |
|---|---|
| 采集 | 听到声音后**固定录 2.4 秒**（带 0.3 秒预录），保住“叮—咚”中间停顿，再裁掉尾部余音 |
| 门控 | 学习时要求比底噪高 **12dB** 才算一次声响；监听时默认 **8dB**（噪声环境更容易触发） |
| 只拒两种 | 太小声（峰值 < -40dBFS）、有效声音太短（< 0.35 秒） |
| 只提示不拒 | 声音偏响（削波）、和上几次差异较大 —— 都会提示，但仍然采用 |
| 次数 | 录满 2 次即完成；最多尝试 8 次；只录到 1 次也算成功（附提示） |
| 阈值 | 按两次录音的一致性算：`一致性 − 0.12`，限幅在 **0.50~0.62**；开始监听时若阈值高于模板一致性推算值，会**自动下调** |
| 模板 | 保存为 `sounds/learned_*.wav`，匹配时自动生成 ±5% 时间伸缩变体 |

> 之前的版本用“相似度硬性拒绝”来保证质量，但环境噪声会让同一种门铃也被判低分，
> 导致“明明没改条件却一直提示错误”。现在改成：只做物理质量检查，一致性只作提示。

**阈值为什么要按一致性算**：同一门铃的两段录音本来就只能到 0.6 左右（手机位置、环境差异）。
如果阈值设在 0.62，现场怎么放都差一点点——表现就是“识别不到”。
现在阈值 = 模板一致性 − 0.12（限幅 0.50~0.62），并且开始监听时会再自检一次：
若保存的阈值高于当前模板推算值，自动下调并在日志里提示，不需要重新学习。

## 四、怎么验证它工作正常

### 快速（2 分钟）

1. 学习门铃（按 2 次）
2. 开始监听，放 5 次门铃 → 应命中，延迟 < 1 秒
3. 说一段话、放一段音乐 → 不应命中

### 严格（使用前）

| 测试 | 做法 | 合格线 |
|---|---|---|
| 麦克风 | 监听时说话，看音量条跳动 | 明显跳动，底噪 -60~-45dB |
| 学习质量 | 一次就出现「学习完成 ✓」 | 不应反复要求重按 |
| 正样本 | 连续放 10 次门铃 | ≥ 8 次命中 |
| 延迟 | 看大字下延迟数字 | < 1 秒 |
| 负样本 | 说话 10s、音乐 10s、敲桌、关门、拍手 | 0 次命中 |
| 稳定性 | 连放 3 次（间隔 3 秒） | 3 次都命中 |

不达标时只动两个滑块（高级设置里）：
- **漏报** → 阈值降 0.03，或门控降到 6~8（噪声环境默认就是 8）
- **误报** → 阈值升 0.03，或门控升到 10~12

### 离线自检（不用麦克风、不出声）

```bat
run.bat selftest
python -X utf8 tools\iot_selftest.py
python -X utf8 tools\board_selftest.py
```

`selftest` 的负样本按麦克风严格管线判定，有失败项时退出码为 **1**；另外两套自测同样以退出码 0 表示通过。

## 五、确定性测试结果（不经过麦克风，直接喂音频）

用同一段门铃生成 2 次带差异的“现场录音”学习，再喂入检测器（50ms 块，阈值 0.50）：

| 场景 | 结果 |
|---|---|
| 正常音量连续 3 次 | **3/3 命中**，score 0.77，声音开始后 **0.4 秒**命中 |
| 小声 + 噪声 | **3/3 命中**，score 0.64，同样 0.4 秒 |
| 白噪声 / 环境响动 | **0 次误报** |
| 学习一致性 | 0.50~0.68 |
**噪声环境专项（学习后的模板，门控 8dB，阈值 0.60）**

| 场景 | 结果 |
|---|---|
| 粉红噪声，信噪比 20 / 10 / 5 dB | 命中 2/3、1/3、2/3，命中时得分 0.81~0.86 |
| 风扇低频噪声，信噪比 20 / 10 / 5 dB | 命中 3/3、2/3、1/3，得分 0.79~0.85 |
| 纯粉红噪声（没有门铃） | **0 次误报**（最好 0.47） |
| 纯低频噪声 | **0 次误报**（最好 0.36） |

> 噪声环境下“有时漏”，主要不是匹配分数问题（5dB 信噪比得分仍有 0.8 左右），
> 而是触发时机：噪声先触发采集、真正的门铃被挤在采集中间。
> 已加入“采集中遇到明显更响的新起音就重新开始采集”，并把默认门控从 12dB 降到 8dB。

> 注意：这是“同一段音频 + 模拟差异”的结果，真实房间里还要按第四节实测一次。

## 八、已知限制（使用时照实说）

- 网页只服务局域网：不暴露公网；手机打不开先检查 Windows 防火墙，或确认页面「设置」里的局域网开关是开的。
- IoT 需要现场在页面填写 `Iot_id` / `Iot_pwd` / 两个主题；仓库不含任何凭证（`sounds/iot.json` 被 gitignore）。
- 学习与识别的现场声学建议不变（见下）；网页只负责展示与操作。
- 只认**学过的那个门铃声音**，不认“所有门铃”；
- 学习时和使用时的**手机位置、音量尽量一致**；
- 电脑喇叭播放时，Windows 回声消除可能把声音从麦克风里抹掉（偶发没反应）——**用手机播放不受影响**；
- 环境很吵时：先降「判定阈值」0.03，再把「门控 dB」降到 6~8；反了会更容易漏；
- 识别基于模板匹配，适用于门铃 / 敲门 / 水壶 / 火警等固定声源；不宣称通用声学识别。

## 十、误报防护：两级判定（重要）

门铃和“大声说话”都有谐波，光看调性不够，所以判定分两条路：

### 路径 A：快速命中（约 0.55 秒）

条件：**匹配分数 ≥ 阈值 + 0.20** 且 **调性 ≥ 3000** 且至少听了 0.4 秒。
真实门铃满足（干净门铃 score 0.98 / 调性 11000+），说话不满足（score 最高 0.51 / 调性 <1000）。

### 路径 B：复核（约 0.9 秒）

条件：分数过阈值、但没达到快路径（例如小声或噪声里的门铃）。
此时继续听到 **0.85 秒**，检查**包络调制**：

| 声音 | 2~8Hz 调制占比（音节起伏） |
|---|---|
| 门铃（1 秒窗口） | 15% ~ 30% |
| 门铃 + 噪声 | ~28% |
| 说话（正常 / 更大声） | **85% ~ 89%** |

调制 ≤ 55% 才判定为门铃。说话的音节一起一伏，会被这条挡掉。

### 界面显示 3.5 秒自动复位

命中后大字「门铃！」显示 **3.5 秒**，然后自动回到「监听中…」，
标题下方保留「上一声门铃 20:22:27」。这样门铃不响了界面不会一直挂着“门铃”。

### 三个地方生效的调性检查

1. **学习时**：调性 < 300 的录音不算门铃（提示“这次不像门铃声”），不存成模板；
2. **命中时**：上面的两级判定；
3. **加载模板时**：自动跳过调性过低的参考音。

> 曾经出现“大声说话被识别成门铃”，原因是语音元音也有谐波、调性不低。
> 加入“包络调制复核”后，说话（含更大声）误报为 0。

**验证结果（50ms 块，阈值 0.50）**：

| 场景 | 结果 |
|---|---|
| 门铃正常 | 3/3 命中，约 0.55 秒，score 0.86 |
| 门铃小声 | 3/3 命中，约 0.55 秒，score 0.74 |
| 说话样（正常） | **0 次误报** |
| 说话样（更大声） | **0 次误报** |
| 白噪声 | **0 次误报** |

## 十二、更多声学参数（v2 判定）

除匹配分数、调性、包络调制外，又加入三个参数，命中要求全部通过：

| 参数 | 含义 | 门铃 | 说话 / 音乐 | 阈值 |
|---|---|---|---|---|
| 包络调制 | 2~8Hz 音节起伏占比 | 15%~30% | 85%~99% | ≤ 50% |
| 衰减速度 | 起音后包络下降 dB/s | -25 ~ -35 | 约 0 | ≤ -8 |
| 音高稳定度 | 最长稳定音高段占比 | 0.2~0.44 | <0.1（音乐 1.0 但主频不符） | ≥ 0.10 |
| 主频比例 | 事件主频 / 模板主频 | 约 1.0 | 说话 0.1~0.2、音乐 0.2~0.3 | 0.5 ~ 2.0 |

实测（模板主频 2469Hz）：

| 场景 | 结果 |
|---|---|
| 门铃正常 | 命中，0.55 秒，score 0.86，主频比 1.00 |
| 门铃小声 | 命中，0.55 秒，score 0.74，主频比 1.00 |
| 说话样 | **0 次误报**（主频比不合格） |
| 音乐样 | **0 次误报**（主频比不合格） |
| 白噪声 | **0 次误报** |

同时把报警冷却从 3 秒加到 **8 秒**，避免同一段持续声音反复报警。

1. 看界面「环境状态」：显示红色/橙色就先解决麦克风增益或环境噪声

## 十六、修复：敲门太小声（实测数据）

### 问题定位

用「扬声器播放 → 麦克风录音」逐类实测，得到麦克风实际收到的信噪比：

| 事件 | 修复前 SNR | 原因 |
|---|---|---|
| 门铃 | +19.5 dB | 正常 |
| **敲门** | **+1.8 dB** | 几乎等于环境噪声，必然漏检 |
| 水壶 | +8.0 dB | 偏弱 |
| 火警 | +31.7 dB | 正常 |

原因：四段内置音频的响度不统一——敲门文件峰值只有 -13dBFS（门铃 -1.8、火警 0），
而且敲门的能量集中在 60~500Hz，笔记本小喇叭根本放不出来。

### 修复

把四段内置音频统一做 **RMS 响度归一化**（目标 -18dBFS，峰值留余量）。

修复后实测：

| 事件 | 修复后 SNR | 提升 |
|---|---|---|
| 敲门 | **+20.4 dB** | **+18.6 dB** |
| 门铃 | +18.3 dB | -1.2 |
| 水壶 | **+13.4 dB** | **+5.4 dB** |
| 火警 | +20.2 dB | -11.5（原来过响，反而更均衡） |

### 新增声学参数

判定用的特征从 5 个扩到 10 个（都写进日志，便于现场排查）：

- 原有：匹配分数、调性、包络调制、衰减速度、音高稳定度、主频比例
- 新增：窄带集中度、低频敲击次数、最短爆破时长、低频调性、脉冲持续时长

### 结论

- **敲门漏检的主因确实是音量**，归一化后信噪比提高 18.6dB
- 但真实环境的房间噪声仍然影响识别：安静音频自检 4/4 全过，
  经扬声器+麦克风后只有火警稳定识别，其余受环境噪声影响
- 建议：在安静环境用「试听」按钮测试，或看界面「环境自检」确认底噪水平

### 2. 播放零处理

构建时用 ffmpeg 把原始文件转成 **48kHz / 44.1kHz 单声道 WAV**（sounds/original/、sounds/original_44k/）。
播放时按设备采样率**直接播放对应文件，不再做任何运行时重采样/滤波**。

之前的杂音根因是运行时重采样：线性插值会产生高频成像，频谱插值会产生梳状失真。
现在常用设备（48k/44.1k）都走零处理路径。

### 3. 播放音量平衡（只调音量，不改音色）

原始录音电平差异大（水壶干净段很轻、火警很响），播放时按类别做音量平衡：
PLAY_GAIN = {doorbell:1.6, knock:4.0, kettle:10.0, fire:0.5}，只影响音量。

### 4. 新增「🔊 测试音」按钮

播放 1 秒 1kHz 纯音。用途：判断扬声器/播放链路是否正常。
- 测试音干净 → 链路正常，剩下的是素材本身
- 测试音也杂 → 检查扬声器/音频增强设置

## 二十二、程序内播放杂音修复

### 根因（两个）

**1. 播放音量放大导致硬削波**

试听播放有音量平衡系数（PLAY_GAIN）。例如门铃原始峰值 -2.4dBFS，
乘 1.6 倍后变成 **+1.7dBFS，超过满量程被硬削平**，听感就是破音/杂音。

修复：新增 prepare_playback()，播放前按实际峰值自动限制增益
（峰值上限 0.85，即 -1.4dBFS），并记录日志「音量自动降到 X（避免削波杂音）」。
实测：门铃增益 1.6 → 1.12，输出峰值 0.85，与源音频相关性 1.0000（无失真）。

**2. 输出流缓冲/声道配置**

- 改为双声道设备按双声道输出（避免单声道→立体声路径异常）
- latency="high"，1024 帧小块写入，降低缓冲不足风险
- 每次写入检查 underflow 标记，日志提示「播放缓冲不足 N 次」

### 播放前数据检查（离线实测）

| 事件 | 源峰值 | 目标增益 | 实际增益 | 输出峰值 | 与源相关性 |
|---|---|---|---|---|---|
| 门铃 | -2.4dB | 1.60 | **1.12** | 0.850 | **1.0000** |
| 敲门 | -13.1dB | 4.00 | **3.83** | 0.850 | **1.0000** |
| 水壶 | -31.3dB | 10.0 | 10.0 | 0.273 | **1.0000** |
| 火警 | 0.0dB | 0.50 | 0.50 | 0.500 | **1.0000** |

相关性 1.0000 说明播放数据与源文件完全一致（只是整体音量缩放），没有失真。

## 二十三、播放时 UI 卡顿修复

### 原因

1. **每次播放都重新打开音频输出流**（实测每次 50~170ms，第一次更慢）
2. **停止监听时在 UI 线程里 join 录音线程**（最长等 3 秒）
3. 播放前的音频加载/准备也在 UI 线程执行

### 修复

| 改动 | 说明 |
|---|---|
| 启动后台**预打开输出流并复用** | 日志只在启动时出现一次「播放设备已就绪（xx ms）」 |
| 播放/音频加载移到后台线程 | UI 线程只做按钮事件 |
| 停止监听改为**后台 join** | UI 立即响应，停止状态稍后完成 |
| 事件轮询每次最多处理 40 条 | 避免一次处理大量事件造成卡顿 |
| 快速连点只保留最新一次试听 | 不会排队延迟 |
